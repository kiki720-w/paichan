# 响应速度优化（2026-08-28）

## 测量与改动

- 线上日志中近期 PUT /api/state 的服务端处理时间为 95–105ms。原状态 JSON 约 357535 bytes，每次保存还会完整返回它。
- 新客户端发送 `Prefer: return=minimal`，成功响应只返回持久化确认、版本和日志；只有收到 `ok:true` 才更新界面。旧客户端仍返回完整状态，恢复备份操作仍返回恢复后的状态。
- 使用当前数据库只读快照估算，精简确认约 6956 bytes，包含整份状态时约 364500 bytes。这是快照计算，不是生产 PUT 压测；没有为测速改写生产任务。
- 同一数据库绑定只初始化一次表结构和迁移；初始化失败会清除缓存，后续可重试。备份、审计、版本冲突检查仍然执行。
- 缓存派工展示行和订单搜索结果，避免弹窗输入时重复计算。
- 在 Nginx 当前站点启用脚本/样式 gzip，未扩大到身份接口 JSON。配置保存在 deploy/nginx-response-compression.conf。参考 https://nginx.org/en/docs/http/ngx_http_gzip_module.html 。

## 线上验证

- 主脚本未压缩 546286 bytes，gzip 后 129142 bytes，减少约 76%。同一环境一次相邻请求分别耗时 4.22s、3.42s；首次压缩请求为 7.19s，网络/冷启动波动明显，不能将该结果当作稳定延迟保证。
- 网站首页 HTTP 200，未登录状态接口 HTTP 401；服务器服务 active，nginx 配置检查通过。
- 服务器回滚备份：/opt/paichan-backups/performance-20260828-203149，包含页面、API 和修改前的 Nginx 配置。
- 构建通过；40 项测试通过，包括真实内存 SQLite 下的精简确认、重新读取、备份、恢复、旧客户端兼容、版本冲突和初始化失败重试，以及客户端等待确认后更新。

## 保留限制

- 仍提交整份工厂状态，上传时间尚未消除；未执行用户登录会话的生产保存操作测速。
- 保持现有服务运行模式和数据库路径；未迁移至生产构建服务，以免在本轮小范围优化中改变持久化环境。
- 全项目原有 Cloudflare 类型声明问题和旧模板测试问题见交接记录。
