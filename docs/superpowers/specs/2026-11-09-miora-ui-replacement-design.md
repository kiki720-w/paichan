# 序衡 APS：Miora 界面替换方案

## 目标与范围

以已提取的 `xuheng-aps-ui-prototype.zip`（13 个 HTML 页面及 README）为界面来源。用户选定全面替换旧界面，不做旧版切换或回退入口。替换的是界面结构、样式和交互呈现，不删除订单、排产数据、历史记录、账号或业务逻辑。

现有 React 页面已经集成账号验证、工厂加载、Excel 导入、排产、人员指定、完工、计划确认、发布、撤回和导出。保留这些实际逻辑及服务端权限、存储接口；不使用原型里的示例数据、模拟登录和只弹提示的保存操作。

## 实现方式

- **采用：把原型页面移植到现有 React 应用。**沿用原型的版式、色彩、导航、表格、状态和操作布局，用现有业务数据驱动。抽出共享布局和样式，移除被替代且无其他消费者的旧 UI 和样式，不保留两套页面。
- **不采用：直接上线 13 个静态 HTML。**原型的 URL 参数仅模拟角色和工厂，导入、排产和导出也不具备真实业务逻辑。
- **不采用：只给旧页面换色。**会保留旧页面结构，与明确的完整替换要求不符。

## 页面与行为

- 登录后由真实会话确定身份；总负责人在看板切换西安／兴平，其他页面只显示当前工厂。工厂负责人绑定所属工厂，无切换入口。切厂后清除前一工厂的选择和临时编辑状态。
- 主链路接通真实登录、MES Excel 导入、订单核对、六工作日车工排产、计划确认、发布及导出。订单状态与计划状态分开。产能缺口有独立可见区，待确认订单显示缺失原因。
- 工序任务、预警、人员产能、工件定额、规则和历史等页面也用新布局承接现有业务。保留六步使用引导，修正原型中“尚未上线”的标记。产品地图是说明页，不是业务模块。
- 交付版不出现本地 MES 模拟按钮，不新增真实 MES 数据库同步入口。开发及测试使用隔离的本地数据，不连接生产存储。

## 验收

1. 登录及登录后的业务页面只显示 Miora 版界面，旧界面没有入口；对照原型检查布局，长表、窄屏和弹窗可正常操作。
2. 两种角色分别测试；总负责人只在看板切厂，切换后目标工厂的数据正确，工厂账号无法访问另一工厂。
3. 使用本地测试数据走完主链路。校验 Excel 确实解析、排产确实更新、发布状态确实保存、导出确实生成文件。
4. 检查资料缺失、产能缺口、整单转派容量不足与完工更正；原有业务测试、构建与新界面回归检查通过。
5. 本次仅交付本地结果，不部署、不修改正式站和生产数据。
