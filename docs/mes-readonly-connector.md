# 序衡 APS：云端 MES 只读接入口

当前采用已确认的「MES 主从复制，序衡只读查询从库」。正常使用的正式数据入口仍为 Excel。没有上线同步任务、远程驱动、凭据、对外写入接口或 MES 回写。

## 已实现

- `app/server/mes-source.ts`：`MesReadSource.read(factory, cursor)` 接收工厂和上次游标，返回已转换的工单快照及下个游标。每条快照包含工厂、稳定业务键、严格递增版本、工单号、物料、名称、数量、累计完工量和交期，可带图号、客户。
- `syncMesPage(factory, source, store)`：新增或合并订单，处理重复、过期、同版本冲突和工厂不匹配。已存在的 Excel 订单必须唯一匹配才会关联，保留人工指定和人工完工记录；差异记录在序衡侧。异常页或写入失败不推进游标。
- `app/server/mes-state-store.ts`：`createMesStateStore(db, initial)` 对接已初始化的 APS D1 表。订单、同步位置、历史备份、审计在同一事务内保存，按工厂和版本防止覆盖并发修改。
- MES 同步不改已有派工、已确认或已发布状态及历史快照。当前计划在页面提示需要核对，重新排产由人触发。
- 同步位置和关联由服务端保存。普通保存不能回退同步位置；已建立同步的工厂会拒绝移除关联订单的清空、导入或直接恢复备份，并提示先核对。Excel 独立使用时保留原行为。

## 接云端前必须落实

1. 根据真实数据库类型、表和字段字典实现只读 `MesReadSource`。先确认工单与工序的唯一键、工厂归属、全量与增量衔接、同时间戳排序与从库延迟；不以轮询结果的行号生成版本。
2. 在隔离联调环境核对已有 Excel 订单如何对应 MES 快照，明确重叠字段以哪边为准、取消、暂停、回退完工及异常恢复口径。当前接口只处理新增和更新，不把某条记录暂时没读到当成删除；恢复备份须先核对订单、版本与同步位置。
3. 由服务端显式启用定时任务和凭据，先用只读账号和测试数据验证断线、重放和并发冲突。不要在浏览器或工作簿里放连接串和密码。

本地验收：`node --test tests/mes-source.test.mjs` 使用模拟源和独立 SQLite 驱动运行同一套事务 SQL。
