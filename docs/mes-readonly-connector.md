# 序衡 APS 的 MES 只读同步

西安与兴平分别使用各自的 MES MySQL 从库。读取任务以只读事务查询工单、工序、计划量与报工，按工厂和 MES 工序 ID 识别记录。同步结果只保存在序衡侧。

- `scripts/mes-order-sync.mjs` 按定时任务更新序衡订单列表。可唯一关联的订单沿用原 ID。人工完工冲突、审批拆单及异常数量进入核对流程。
- `scripts/mes-catalog-poll.mjs` 分页建立工单目录，保留历史工序，随后增量读取工单、工序及报工的变化。SQLite 保存同步位置和数据版本，支持重启后继续读取。
- `scripts/mes-catalog-service.mjs` 提供按工厂隔离的历史、待排和待核对查询。数据变化后使用序衡已有定额和产能生成新版草稿。
- 新草稿需要人工确认后才能发布。确认与发布时均复核 MES 版本和序衡状态，保留现有订单标识、派工及历史计划。已有未发布派工会在合并草稿中单独列出，随人工发布的合并版本生效。

## 服务配置

`deploy/xuheng-mes-sync.service` 和对应的 `.timer` 负责订单更新，`deploy/xuheng-mes-catalog.service` 负责全量目录采集和草稿服务。`deploy/mes-catalog-proxy.conf` 为序衡站点启用回环地址上的目录接口。两个服务使用仓库中的 `mysql2` 依赖，部署目录需要包含 `scripts/` 和 `app/server/`。草稿服务还通过 `MES_CATALOG_APP_ROOT` 读取当前序衡排产逻辑。

站点会话配置和 MES 只读凭据由部署环境提供。发布前在隔离副本验证数量更新、草稿确认、保留原有计划和故障恢复。工序数量异常、疑似重复报工继续由 MES 方核对。工时和设备主数据由序衡现有配置提供。

运行 `npm test` 可验证工单合并、异常隔离、草稿版本与发布保护。
